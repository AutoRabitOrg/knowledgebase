# Register Salesforce ORG - Client Credentials Flow

_Configure a server-to-server Salesforce connection through an External Client App and validate the connection in AutoRABIT Vault._

## Overview

The Client Credentials Flow registers a Salesforce org in AutoRABIT Vault by using the Client ID and Client Secret from a Salesforce External Client App. The flow is designed for server-to-server authentication and does not require an interactive user sign-in.

{% hint style="info" %}
The screenshots contain example environment values. The user enters the values for the target Salesforce org and uses the Callback URL generated by the active Vault environment.
{% endhint %}

### Workflow

1. Enter the Salesforce environment details
2. Create and configure a Salesforce External Client App
3. Enter the Client ID and Client Secret in Vault
4. Review and verify the credentials
5. Confirm registration and test the API connection

## Prerequisites

1. Access to **Setup** in AutoRABIT Vault.
2. Permission to create and configure an External Client App in Salesforce.
3. A Salesforce Run-As user with the **API Enabled** permission.
4. The Salesforce **My Domain URL** for the target org.
5. The Salesforce API version required for the connection.

{% hint style="warning" %}
The Run-As username configured in the Salesforce External Client App must match the User Name entered in Vault.
{% endhint %}

### Enter the Environment Details

1.  For **Environment Type**, select **Salesforce**.

    <figure><img src="../../../../.gitbook/assets/image (2788).png" alt=""><figcaption></figcaption></figure>

&#x20;                                          Select Salesforce as the environment type.

2.  From **Salesforce API Version**, select the required API version.

    <figure><img src="../../../../.gitbook/assets/image (2789).png" alt=""><figcaption></figcaption></figure>

&#x20;                                          Select the Salesforce API version.

3. Enter a descriptive value in **Org Title**.

**My Domain URL:** The user enters the My Domain host displayed for the target Salesforce org. Vault determines whether the org is Production or Sandbox from this URL.
{% endhint %}

{% step %}
### Configure the Salesforce External Client App

The Salesforce Admin Setup step displays the settings required for the External Client App. The Salesforce administrator completes the configuration in the target Salesforce org.

1. In Salesforce, navigate to **Setup > App Manager**.
2. Create a new External Client App by selecting **New External Client App**.
3. Enable the **OAuth Plugin**.
4.  Choose **Client Credentials** as the OAuth flow.

    <figure><img src="../../../../.gitbook/assets/image (2791).png" alt=""><figcaption></figcaption></figure>

&#x20;                                       Review the initial Salesforce External Client App instructions.

5. Copy the **Callback URL (Redirect URI)** displayed in Vault and add it to the External Client App.
6. Add all required OAuth scopes listed in Vault.
7. Under **Policies > Plugin Policies**, set **Permitted Users** to the required access option.
8. Under **OAuth Flows and External Client App Enhancements**, enable **Client Credentials Flow** and specify the Salesforce username in **Run As (Username)**.
9. Under **App Authorization > IP Relaxation**, select the appropriate IP relaxation option.
10. Save the app, and copy its Client ID and Client Secret.

    <figure><img src="../../../../.gitbook/assets/image (2792).png" alt=""><figcaption></figcaption></figure>

&#x20;                                      Configure OAuth scopes, policies, Run-As user, and IP relaxation.

#### Required Callback URL and OAuth Scopes

1. Select **Copy** to copy the Callback URL shown by Vault.
2.  Add the following scopes to the External Client App:

    * Access the identity URL service (id, profile, email, address, phone)
    * Manage user data via APIs (api)
    * Manage user data via Web browsers (web)
    * Full access (full)
    * Perform requests at any time (refresh\_token, offline\_access)

    <figure><img src="../../../../.gitbook/assets/image (2793).png" alt=""><figcaption></figcaption></figure>

&#x20;                                      Copy the Callback URL and confirm the required OAuth scopes.

### Enter the Client Credentials

1. In Salesforce, navigate to **Setup > App Manager**.
2. Locate the External Client App, open its dropdown menu, and select **View**.
3. Select **Manage Consumer Details** to reveal the credentials.
4. Copy the Consumer Key and Consumer Secret from Salesforce.
5.  In Vault, enter the Consumer Key in **Client ID** and enter the Consumer Secret in **Client Secret**.

    <figure><img src="../../../../.gitbook/assets/image (2796).png" alt=""><figcaption></figcaption></figure>

&#x20;                                      Enter the Client ID and Client Secret.

{% hint style="warning" %}
**Security:** The Client Secret is sensitive. It is entered only in the Client Secret field and is not included in documentation or shared through unsecured channels.
{% endhint %}

6.  Select **Continue**.

    <figure><img src="../../../../.gitbook/assets/image (2797).png" alt=""><figcaption></figcaption></figure>

&#x20;                                      Continue to credential verification.
{% endstep %}

## Troubleshooting

<details>

<summary>Redirect URI Mismatch</summary>

The Callback URL is copied exactly, including the protocol and trailing path. Extra spaces or characters are removed.

</details>

<details>

<summary>Missing refresh_token Scope</summary>

All OAuth scopes listed in Vault are added to the Salesforce External Client App.

</details>

<details>

<summary>API Not Enabled for User</summary>

The connecting Salesforce user has the API Enabled permission in the user's profile.

</details>

<details>

<summary>Invalid Client ID Error</summary>

The Client ID and Client Secret may require time to propagate in Salesforce. The user waits briefly and tries again.

</details>

<details>

<summary>Limit Idle Refresh Token TTL to 30 Days</summary>

When this setting is enabled, an unused refresh token expires after 30 days and the Salesforce org must be authenticated again.

</details>

## Expected Result

The Salesforce org is registered in AutoRABIT Vault through the Client Credentials Flow. Vault confirms the registration and, when the API test is run successfully, displays a successful connection notification.
